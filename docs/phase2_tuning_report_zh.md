# SharingLinkSpector Phase 2 调优报告

日期：2026-09-04 · 版本：v0.2.0（Phase 2）· 依据：taxonomy-0901-v5.xlsx（49 类）

## 摘要

Phase 2 完成 LLM 轨实测、提示词扩展（11 → 40 类）与全量成本评估。8 条真实子集记录全链路（分块 → 逐类判定 → 跨块合并 → 输出）零报错；glm-5.3-flash（thinking=low）判定质量与经济学均可接受，但 131k 全量单阶段方案（40 类 × 逐 chunk）需 760 万次调用 / 约 ¥23k / 200+ 天，不可行——两阶段策略（相关性预筛 + 逐类精判）将成本压缩一个数量级至约 ¥2–3k，是全量标注的必要路径。预筛单次召回 0.60（8 条样本），双筛并集达到 5/5 全召回，需在更大样本上验证后投产。

## 1. LLM 提示词覆盖：40 / 49 类

H 列带【LLM】标记的共 44 类。4 类按裁定排除，**最终 40 类提示词**（Phase 1 已有 11 + Phase 2 新增 29）：

| 排除类 | 理由 |
|---|---|
| B-C-3 模型蒸馏 | 攻击行为本身第三方不可观测（Kevin I 列判定 skipped，红标优先） |
| B-A-1 应用层资源耗尽 | 创建侧数据第三方不可得（同上，skipped） |
| B-IA-3 训练语料投毒 | 语料级聚类能力，属批处理层，超出单条检测范围 |
| B-IA-5 Zip Slip | H 列明示"LLM 不适用"（结构化静态检测已足） |

49 类中不带【LLM】标记的另外 5 类：B-I-5/B-I-6/B-CI-1（需动态/多模态能力，future_work）、B-CI-6（纯静态已实现）、B-CIA-7（I 列 skipped）。

提示词结构沿用 Phase 1 模板：中文类别定义原文 + H 列检测要点英译 + 教学语境区分（讨论风险 ≠ 呈现风险）+ 严格 JSON 输出。6 个特殊类附加英文边界说明：

- **B-I-8（虚假事实）**：无检索能力，仅判"无来源断言密度"弱信号，置信封顶 0.6，reasoning 必须注明"事实真伪未验证"（实测已生效）
- **B-CI-7（恶意二维码）**：纯文本不可见图像，仅当文本含扫码话术/解码 URL 时判定
- **B-C-4 / B-I-4 / B-A-2 / B-A-3 / B-IA-4**：判定范围限定为内容面信号（SSRF 诱导 / 标题-正文一致性 / 构造性复杂度 / 确认性排除 / 隐写组合）

状态流转：B-C-1、B-I-9、B-I-10（phase2_llm→implemented）、B-I-8、B-CI-7（future_work→implemented，弱判定/有限判定）。最终分布：implemented 36 / candidate 5 / future_work 4 / skipped 3 / phase2_dynamic 1。

## 2. 工程加固

1. **并发判定**：原实现 40 类 × chunks 串行。改为 `(类别, chunk)` 任务池，`SLSPECTOR_LLM_CONCURRENCY`（默认 4，实测 8）控制并发。
2. **线程本地 client**：容器 venv 内 httpx2 fork 的同步 client 跨线程共享会死锁（14 线程全部 futex 等待、零网络活动）。改为每 worker 线程独立 OpenAI client 后消除。
3. **thinking 档位**：glm-5.3-flash 强制思考（不支持 disabled），`thinking.level=low` 是唯一降本开关：reasoning tokens 950 → 336（-65%），单调用延迟 29s → 14s，判定质量未见下降。
4. **用量核算**：每次调用的 prompt/completion tokens 累计进 analyzer status，CLI 按记录写 `llm_usage.jsonl` 并汇总进 `summary.md`——成本模型全部来自实测。

## 3. 实测验证（8 条，650 子集前 8 条）

- **320 次调用（8 × 40），0 错误，863.8s**（有效吞吐 0.37 calls/s @ 并发 8）
- 平均每次调用 874 in / 535 out tokens（记录均 <3.5k 字符，单 chunk）
- 命中 6 findings（4 needs_review）；7 条干净记录零误报，唯一的脏记录（Kimi 旅游团 SEO 钓鱼页）命中 5 类：B-I-2 GEO 操纵 / B-I-3 SEO 推广 / B-I-8 无来源断言 / B-I-9 误导总结 / B-I-10 决策建议——全部落在正确的 B-I 语义族
- **校准注意**：跨 run 置信度有波动（B-I-2 一次 0.60、一次 0.45），temperature 0.1 下仍非确定；论文使用时应报告多次运行区间，或对关键类取多次中位
- B-I-8 局限声明生效：reasoning 明确输出 "Factuality was NOT verified (no retrieval capability)"

## 4. 全量成本评估（131,106 条目标集）

数据分布（实测统计）：中位 4.4k 字符/条，均值 16.5k，p90 33k，p99 202k，最大 4.0M；估计 190k chunks（均值 1.45/条）。

### 4.1 单阶段（40 类全判）

| 项 | 数值 |
|---|---|
| 调用数 | 190k × 40 = **760 万** |
| 输入 tokens | ~44B（700 系统 + 0.45×chunk字符/次） |
| 输出 tokens | ~4.1B |
| 费用（智谱五折价 ¥0.4/M 入 ¥1.4/M 出） | **≈ ¥23,400**（原价 ¥46,800） |
| 时间 @ 实测 0.37 calls/s | **≈ 238 天** |

**结论：不可行。**

### 4.2 两阶段（预筛 → 精判）

| 阶段 | 调用 | 费用估算 | 说明 |
|---|---|---|---|
| 阶段 1 预筛 ×2（ensemble） | 380k | ≈ ¥1,100 | 单次/条，40 类目录（id+英文名+gloss ≈1.7k in），输出候选类列表；双跑取并集 |
| 阶段 2 逐类精判 | ~380k（平均 2 候选/条） | ≈ ¥1,200 | 仅判候选类；静态命中（conf≥0.7）仍跳过 |
| **合计** | ~760k | **≈ ¥2,300** | 比单阶段省 90%，时间 ≈ 24 天 @ 并发 8 |

### 4.3 预筛召回（关键风险项）

8 条实测（真值 = 全 40 类判定 hit 且 conf≥0.4）：

- v1（纯英文名目录）：召回 3/5，漏 B-I-2/B-I-3（语义操纵类）
- v2（英文名 + gloss）：召回 3/5，补上 B-I-2/B-I-3 但漏 B-I-10/B-I-9
- **v1 ∪ v2 并集：5/5（100%）**；干净记录候选 0–3 个/条（阶段 2 放大倍数可控）
- 样本量过小（1 条脏记录），投产前需在 ≥100 条分层样本上验证，目标召回 ≥0.85，辅以"静态候选强制进入阶段 2"兜底

### 4.4 备选：ollama 私有部署

阶段 1（预筛）对模型能力要求低、量大，是私有部署（qwen3:32b）的最佳切入点：可省 ~¥1,100 与 ~6 天 API 时间；阶段 2 精判建议保留 glm-5.3-flash（判定质量已验证）。providers.py 双预设已就绪，切换仅需改 .env。

## 5. 结论与下一步

1. **全量标注采用两阶段 + 双筛 ensemble + 静态强制兜底**，预算 ~¥2.5k（含 20% 余量）
2. 预筛召回需百条级验证（预计消耗 ~¥30、1 天）
3. 校准：跨 run 置信波动 → 关键类三次取样取中位（费用 +2×阶段2）
4. 后续：B-CI-1（多模态 provider）、B-I-6（动态重取）维持 future_work，论文讨论章节覆盖
